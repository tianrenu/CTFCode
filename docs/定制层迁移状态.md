# OpenCode 底座、CTF 定制与当前验收状态

## 当前：preview.4 正式命名入口与TUI开始页

新版本基于OpenCode 2.3.0源码和公开补丁编译 `2.3.0-ctfcode.2`，不再仅用旧版原EXE加插件。原生 `/cd`、空白会话策略、原目录归档、统一模型控制中心、实时状态、执行取证、摘要连续性与既有资源保护均已接入同一套独立TUI；不影响桌面版。

- 对外主入口为带图标的 `CTFCode.exe`，打开即进入TUI开始页；原3/7号BAT只保留兼容，不再作为下载用户的主入口，也没有新增BAT。
- 开始页统一提供模型选择、分片校验/pack准备、题目目录和模型启动。准备前明确确认写入；`/ctf progress` 看进度/日志，`/ctf stop` 取消并保留部分文件；不要求普通用户拼PowerShell命令。
- 本机原3/7号入口已经切换、实际打开TUI并复核新会话与正常退出；不另增顶层BAT，不影响桌面OpenCode。
- 每次打开/切换目录都是空白新会话，旧记录保存在原工作目录，每会话独立；附件、脚本、成果不删除，也不自动恢复旧消息。
- 当前便携布局已经真实完成32K生成、写脚本/执行/读回、卸载后重载，以及64K生成与运行中停止；SHA256由宿主独立复核。完整记录及失败修复见[TUI整合进度](TUI整合进度.md)，不把合成SSE测试当作模型解题结果。
- 模型和本机配置不随包发布；包内带定制CLI、Python、两档签名引擎、必要分析库和中英文原许可。首次只有GGUF时仍须按指南准备一次pack，不宣传尚未验证的自动安装。
- 64K保持显式候选；没有把短测说成近满窗口长期稳定、独立解题能力或另一台机器开箱即用的证明。

新版本的源码构建、打包和使用方法分别见[定制CLI构建](定制CLI构建.md)与[便携版使用](便携版使用.md)。以下保留preview.2的历史范围，避免把当时未完成项目与当前进展混淆。

## 历史：preview.2 定制层进入便携测试版

`v0.1.0-preview.2` 将原工具箱的运行控制、配置和插件迁入 `portable/`，并提供包含 CLI、Python、Strata、两档引擎与依赖的 [Windows 便携包](便携版使用.md)。不再要求普通用户单独安装原版 CLI 或复制作者的配置路径。

这不是重新编译或宣称重写整个 OpenCode：**上游 CLI 是底座，我们的改动由同包的运行控制和插件自动加载。** 只运行包里的 `opencode.exe` 会绕过定制，应使用 `3_CTF做题界面.bat`。

## 打包方式

`script/portable.py` 从固定哈希上游包、npm integrity、Python wheel SHA256 及显式引擎目录组装白名单文件，保留签名和许可证，生成 `bundle-files.json`。BAT 输出为 CRLF，并显式使用隔离 Python 的 UTF-8 模式。

这个方式既不把整个作者工作目录压缩上传，也不让用户重新拼装底座与定制。第三方二进制只放 Release，不进入 Git 源码仓库。

## preview.2当时未通过的门槛

- 新便携布局下真实模型的 GPU 加载、取消/续聊/停止/退出清理全流程。
- 新布局中的近满 64K 长任务、速度波动和多应用共享资源测试。
- 首次从两个分片生成 pack 的完整新机流程，以及另一台干净电脑安装。
- 新的定制模型管理 TUI；目前使用原两入口与上游 TUI，不宣称已经完成界面改造。

因此称为**便携测试版**，不继承旧环境“已通过”的结论，也不承诺稳定 `10+ token/s`。具体本轮通过项见[使用与验收说明](便携版使用.md)。

## 历史纠正：preview.1

首个 `v0.1.0-preview.1` 只有上游源码与基础下载文档，确实没有交付本机定制层，不能复现作者当时环境。这是发布范围错误；相关 Release 已注明缺口，旧标签及校验值保留不变。它不能替代现在的便携包。
