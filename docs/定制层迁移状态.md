# OpenCode 底座、CTF 定制与当前验收状态

## 当前：定制层已进入便携测试版

`v0.1.0-preview.2` 将原工具箱的运行控制、配置和插件迁入 `portable/`，并提供包含 CLI、Python、Strata、两档引擎与依赖的 [Windows 便携包](便携版使用.md)。不再要求普通用户单独安装原版 CLI 或复制作者的配置路径。

这不是重新编译或宣称重写整个 OpenCode：**上游 CLI 是底座，我们的改动由同包的运行控制和插件自动加载。** 只运行包里的 `opencode.exe` 会绕过定制，应使用 `3_CTF做题界面.bat`。

## 打包方式

`script/portable.py` 从固定哈希上游包、npm integrity、Python wheel SHA256 及显式引擎目录组装白名单文件，保留签名和许可证，生成 `bundle-files.json`。BAT 输出为 CRLF，并显式使用隔离 Python 的 UTF-8 模式。

这个方式既不把整个作者工作目录压缩上传，也不让用户重新拼装底座与定制。第三方二进制只放 Release，不进入 Git 源码仓库。

## 仍未通过的门槛

- 新便携布局下真实模型的 GPU 加载、取消/续聊/停止/退出清理全流程。
- 新布局中的近满 64K 长任务、速度波动和多应用共享资源测试。
- 首次从两个分片生成 pack 的完整新机流程，以及另一台干净电脑安装。
- 新的定制模型管理 TUI；目前使用原两入口与上游 TUI，不宣称已经完成界面改造。

因此称为**便携测试版**，不继承旧环境“已通过”的结论，也不承诺稳定 `10+ token/s`。具体本轮通过项见[使用与验收说明](便携版使用.md)。

## 历史纠正：preview.1

首个 `v0.1.0-preview.1` 只有上游源码与基础下载文档，确实没有交付本机定制层，不能复现作者当时环境。这是发布范围错误；相关 Release 已注明缺口，旧标签及校验值保留不变。它不能替代现在的便携包。
