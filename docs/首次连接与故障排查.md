# 首次连接与故障排查

[返回部署指南](README.md) · 上一步：[引擎下载与配置](引擎下载与配置.md)

**正常使用请转到[便携版使用](便携版使用.md)：便携包已自带 CLI 和定制，不需要执行本页的原版 CLI 下载步骤。下面仅保留基础连接/开发排障资料。**

> **仅供基础连通性验证，不是便携版安装流程。** 下面下载的上游 CLI 不会自动获得 CTF 插件、日期缓存修复、状态显示或资源/生命周期管理。完整定制已进入 `portable/`，正常用户使用[便携版](便携版使用.md)，本页不复现整套优化。

## 1. 独立下载 OpenCode CLI，不改桌面版

上游固定版是可选的基础测试依赖，不是完整的 CTFCode 发行物。只有需要自行验证模型接口时才按本章操作；便携版已经随包提供 CLI 并自动加载定制，无需本节下载。

- [OpenCode v1.2.26 Release](https://github.com/anomalyco/opencode/releases/tag/v1.2.26)
- Windows x64 CLI：[opencode-windows-x64.zip](https://github.com/anomalyco/opencode/releases/download/v1.2.26/opencode-windows-x64.zip)
- 不支持该 CPU 指令集时使用同 Release 的 [opencode-windows-x64-baseline.zip](https://github.com/anomalyco/opencode/releases/download/v1.2.26/opencode-windows-x64-baseline.zip)，不要两份混装。
- **不要下载 `opencode-desktop-windows-x64.exe`**，它是桌面安装器，不是本指南的独立 CLI。

2026-11-15 对照 GitHub Release API 的压缩包 SHA256：

```text
opencode-windows-x64.zip
4cdd79773a21a73847e1024ba689d305cdc96e8100729bd89bca4cf1fd5b8256

opencode-windows-x64-baseline.zip
e3baa02d6cdbe99a210ad97e8487de076f8a827e28058dad9df2c7c8df0c88c0
```

下载后用 `Get-FileHash -LiteralPath <压缩包路径> -Algorithm SHA256` 对照。解压到 `$Data/runtime/opencode-1.2.26`，以实际包含 `opencode.exe` 的目录为准。无需替换现有 CLI，不加全局 PATH，不运行桌面安装器。

## 2. 引擎先就绪，再连 Agent

沿用前两章的路径变量。先在引擎启动命令正常完成后检查：

```powershell
& curl.exe --noproxy '*' --fail --max-time 15 'http://127.0.0.1:18791/health'
if ($LASTEXITCODE -ne 0) { throw 'health 未通过，请先检查引擎本轮启动输出。' }
& curl.exe --noproxy '*' --fail --max-time 15 'http://127.0.0.1:18791/v1/models'
if ($LASTEXITCODE -ne 0) { throw '模型列表未通过，先不要启动 OpenCode。' }
```

`health=200` 只证明接口可达，**不单独证明预热已完成、生成正常或做题成功**。还要确认启动器正常返回、模型列表正确，并完成下方短生成测试。`/v1/models` 应包含示例中的 `qwen3.8-flash-next-coder-iq1_m`；如果引擎实际返回不同 ID，修改本机配置的模型键、`model` 和 `small_model` 三处使其一致，不要填模型文件路径。

## 3. 独立配置与会话，不污染桌面版

使用一个**新开的、专用于本项目的 PowerShell**。沿用前文 `$Repo`、`$Data`；若新开了终端，按前文重新设置它们。以下配置只对这个终端及子进程生效，退出终端即结束，不用 `setx`。

```powershell
$Cli = Join-Path $Data 'runtime/opencode-1.2.26/opencode.exe'
if (-not (Test-Path -LiteralPath $Cli)) { throw '请将 $Cli 改为刚解压的独立 opencode.exe 的真实路径。' }
$dir = Join-Path $Data 'opencode'
New-Item -ItemType Directory -Path $dir -Force | Out-Null
foreach ($key in @('config', 'data', 'cache', 'state')) {
    $path = Join-Path $dir $key
    New-Item -ItemType Directory -Path $path -Force | Out-Null
    [Environment]::SetEnvironmentVariable("XDG_$($key.ToUpper())_HOME", $path, 'Process')
}

$env:OPENCODE_CONFIG = Join-Path $dir 'opencode.json'
if (-not (Test-Path -LiteralPath $env:OPENCODE_CONFIG)) {
    Copy-Item -LiteralPath (Join-Path $Repo 'config/opencode.example.json') -Destination $env:OPENCODE_CONFIG
}
# 避免当前终端继承到其他实例的内联配置或插件目录。
Remove-Item -LiteralPath Env:OPENCODE_CONFIG_CONTENT -ErrorAction SilentlyContinue
Remove-Item -LiteralPath Env:OPENCODE_CONFIG_DIR -ErrorAction SilentlyContinue
$env:OPENCODE_DISABLE_AUTOUPDATE = 'true'
$env:OPENCODE_DISABLE_MODELS_FETCH = 'true'
$env:OPENCODE_DISABLE_DEFAULT_PLUGINS = 'true'
$env:OPENCODE_DISABLE_LSP_DOWNLOAD = 'true'
$env:OPENCODE_DISABLE_CLAUDE_CODE = 'true'
$env:OPENCODE_DISABLE_PROJECT_CONFIG = 'true'
$env:NO_PROXY = '127.0.0.1,localhost'

& $Cli --version
```

示例配置只有本地 provider，`model` 与 `small_model` 指向同一模型，关闭自动更新及会话分享，不引用作者本机插件/解释器路径。`OPENCODE_DISABLE_PROJECT_CONFIG` 不等于完整沙箱，仍应先人工审查题目目录和祖先目录中的 `.opencode`、`AGENTS.md`、`CLAUDE.md` 等文件，不让不可信附件伪装成本地配置或指令。

**权限说明：**公开示例允许常规读取/搜索，命令和修改默认 `ask`，这是跨机器的安全起点，不是作者旧环境的免确认白名单。不要改成全局 `allow` 来执行陌生附件；OpenCode 权限匹配不提供操作系统级隔离。未知 PE 在虚拟机/受限仿真环境中分析。

## 4. 在题目副本中启动并验收

```powershell
# 此处可交互输入路径，避免照抄作者机器路径。
$Task = Read-Host '输入独立的、已授权且已审查的题目副本目录绝对路径'
if (-not [IO.Path]::IsPathRooted($Task)) { throw '请使用绝对路径。' }
if (-not (Test-Path -LiteralPath $Task -PathType Container)) { throw '题目目录不存在。' }
& $Cli $Task
```

不要把盘根、用户主目录、源码仓库、模型目录或整个工具箱选为题目目录。在 TUI 中先完成小测试：

1. 输入“只回复：本地连接成功”。应正常输出并结束，不应一直旋转或留下后台请求。
2. 请它读取题目副本内一个无害文本文件，核对读到的内容与实际文件一致。
3. 请它在副本内创建 `CTF_STATE.md` 并读回，人工确认后核对文件内容；不要用未知程序测试执行能力。
4. 生成过程中测试一次取消，确认后台没有继续输出；再发一个短问题，检查续聊可用。
5. `/exit` 退出 TUI，再按引擎指南停止 `ctf32`，检查 `launch --status` 和显存，确认没有重复驻留。

这些才是本机基本验收，不能用配置文件存在或 `/health` 成功代替。首次运行仍可能需要获取上游依赖；当前没有承诺完整离线发行包。

## 5. 上下文怎么设？

| 路线 | 引擎物理窗口 | 示例 OpenCode 软窗口 | 最大输出 | 大约开始摘要的位置 |
| --- | ---: | ---: | ---: | ---: |
| 32K 基线 | 32,768 | 24,576 | 4,096 | 20,480 |
| 64K 候选 | 65,536 | 65,536 | 4,096 | 61,440 |

公开示例只默认开启 OpenCode 自带 `compaction.auto/prune`，**不是**旧运行链全部压缩/缓存插件。摘要有损，需把已验证事实和证据路径保存在题目目录的 `CTF_STATE.md` 中。软窗口、输出上限不意味着原始附件能一次性填满窗口。

32K 成功后要试 64K：先按上一章停止基线、切换候选引擎并以 `--context 64k` 启动，再备份自己的 `$env:OPENCODE_CONFIG`，把该模型的 `limit.context` 改为 `65536`（`limit.output` 仍为 `4096`）。退出并重启 TUI 使配置生效。只改 JSON 而没切引擎会导致溢出；只加窗口也不会令模型更聪明。

缓存命中可减少**实际重新计算**的 token，但缓存 token 仍属于逻辑上下文长度，可能出现在 API 用量中。日期、系统提示、工具清单或历史编辑改变公共前缀时，缓存可能失效；大段冷输入仍会慢。旧环境相关修复尚未完整移植，不能保证本仓库已消除此类重算。

## 6. 常见问题

| 现象 | 先检查什么 | 不要做什么 |
| --- | --- | --- |
| `connection refused` / 无模型 | 引擎启动退出码、18791 监听、`/health`、`/v1/models` | 不要把端口改成 Burp 的 8080 |
| `model not found` | API 实际 ID 与本机配置的三处引用是否一致 | 不把 GGUF 路径当 API 模型名 |
| 缺 `experts.bin` / tokenizer | pack 准备是否成功、目录是否完整 | 不只拷一个 GGUF 或 `strata.exe` |
| DLL/驱动错误 | 包是否完整、`components engine --full`、驱动版本 | 不从第三方 DLL 站点补文件或关闭签名 |
| `EngineMissing` / 签名不通过 | `STRATA_COMPONENTS_DIR`、解压层级、manifest、所选版本 | 不设跳过校验的环境变量 |
| 显存不足/专家缓存缩到 0 | 是否另有模型、GPU 应用，当前空闲显存及内存 | 不降预留强开，不杀未知进程 |
| 两模型一起占显存 | `nvidia-smi`、Strata 状态、其他推理软件的驻留模型 | 不以为切换 UI 模型就会卸载旧模型 |
| 首次回复长时间无字 | 本轮日志是否在冷预读、磁盘忙碌/系统换页 | 不重复发送相同的大请求堆积队列 |
| `context length exceeded` | 物理/软窗口、工具输出是否太长、摘要是否真的触发 | 不仅改 `limit.context` 就声称支持更长窗口 |
| 想清空重试 | 先取消当前生成，`/new` 新会话，仅带入已核实事实 | 不把旧失败推理全文重新粘进来 |
| 改配置没生效 | 是否改到独立配置，是否已退出并重启 TUI | 不去覆盖桌面版/全局配置 |
| 用着用着停止 | 退出原因、命令失败、步数上限（示例 60）及资源 | 不把到步数上限当解题完成 |

报告故障时附：组件版本、模型文件校验结果、启动本轮退出码、去敏错误、可用内存、`nvidia-smi` 和是否使用 32K/64K。不要上传账号、密钥、真实客户日志或未授权网络数据。
