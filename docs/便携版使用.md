# Windows 便携测试版：不用自己拼装

[下载 v0.1.0-preview.4](https://github.com/tianrenu/CTFCode/releases/tag/v0.1.0-preview.4)

本页对应独立原生TUI版，不适用于旧preview.2的外部控制台入口。

## 下哪个包？

下载 **`CTFCode-v0.1.0-preview.4-windows-x64.zip`**，不是 GitHub 自动提供的 Source code。压缩包约1.48GB，解压约2.46GB（十进制），已经包含：

- 带图标与版本信息的 `CTFCode.exe`，直接进入原生TUI开始页，不额外安装Web或桌面运行时。
- 从OpenCode 2.3.0源码编译的 `2.3.0-ctfcode.2`，不是原版EXE改名；修改自动日期、Windows `/cd` 和退出提示。
- TUI内的模型启停、32K默认/64K候选、实时状态、资源自检及独立会话归档。
- 自动压缩、稳定摘要前缀、本会话原始要求与工具证据索引；不预装解题答案或解码算法。
- Python、Strata Control、两档CUDA 13 native engine；不再要求安装旧版npm插件依赖。
- `pefile`、Capstone、Unicorn 及其许可；Unicorn 对应版本源代码随包保留。

**不需要额外安装原版 OpenCode、Python、Bun 或 npm。不包含模型权重或模型 packs。**

## 只需要这样用

1. 将整个包解压到自己的可写 SSD 目录，保持内部目录结构。
2. 准备模型：[IQ1_M 两个分片下载与校验](模型下载与校验.md)，合计约 58.4GB。已有模型可直接复用，不移动或复制。
3. 双击 **`CTFCode.exe`**，开始页按顺序引导“配置本地模型 → 校验分片并准备模型 → 打开题目文件夹 → 启动本地模型”；无需在外部终端输入命令。已有完整pack时跳过准备。
4. `/ctf setup` 可重开向导；`/ctf` 管理模型，`/cd "题目副本完整路径"` 换题。未启动模型时不提前占用模型显存；原3/7号BAT仅保留兼容，不是新用户主入口。
5. `/ctf stop` 停止任务并卸载模型，TUI继续保留；`/exit` 归档并退出。**`7_自检.bat`** 可从外部查看状态，输入 `S` 会归档并关闭本包会话，不会关闭其他应用。

### 首次只有GGUF时：界面内准备pack

在开始页选择模型根目录（里面包含 `IQ1_M`），再确认“校验分片并准备模型”。程序完整计算两分片SHA256，然后调用内置Control准备pack，不需要自己拼PowerShell命令。`/ctf progress` 看百分比、输出与失败原因，`/ctf stop` 可取消；部分pack与日志保留，不删除权重或自动重来。

需要至少16GiB可用RAM和充足SSD空间。准备进程树上限为单进程8GiB/总计10GiB、最长4小时，仅作用于本轮新建进程。另一台干净电脑的首次完整pack准备仍未实测，取消/失败回归不能当作其成功证明。

### 可选：开发/排障命令（普通用户无需执行）

在解压后的包根目录打开PowerShell，把示例模型路径替换成实际路径：

```powershell
& '.\本地模型配置与日志\Strata验证\runtime\control-0.1.52\python\python.exe' -I -X utf8 '.\bootstrap.py' setup --model 'D:\CTF模型\GSQ-RCO-Coder' --prepare
```

它先完整校验两个分片，再准备pack，不启动推理、不另下载权重。已有完整pack时跳过。首次从两分片准备的耗时取决于SSD/内存；本版仍未在另一台干净电脑验证该全流程，不声称“一键自动安装”已验收。

### TUI常用操作

| 需要做什么 | 操作 |
| --- | --- |
| 模型、上下文与自检 | `/ctf` 打开统一菜单；也可输入 `/ctf status` |
| 首次配置与准备进度 | `/ctf setup`、`/ctf prepare`、`/ctf progress`；写入pack前必须确认 |
| 加载/卸载 | `/ctf start`、`/ctf stop`；停止输出不等于卸载 |
| 选择32K/64K | `/ctf 32` 或 `/ctf 64`；先停止卸载、重载配置、再新建会话，不同时加载两个模型 |
| 换题目或重开同目录 | `/cd "完整路径"`；必须先停止当前任务 |
| 同目录换方向、清空上下文 | `/new`，重新描述任务和要保留的已验证事实 |
| 看旧记录 | 在原工作目录的 `.ctfcode/会话归档` 打开每个会话的 `阅读.md`；`会话.json` 是原始结构，`校验.json` 是哈希 |

每次启动、打开/切换目录、重开同目录和 `/new` 都从空白会话开始；不自动恢复旧上下文。附件、脚本和成果仍留在题目目录。旧会话每个独立子目录，不会混写；归档失败或任务仍运行时拒绝切换。断电/强杀不属于正常退出，尚未落盘的最后一段不能保证保存。

不要只运行 `程序/opencode.exe`：那会绕过 CTF 运行控制和插件注入。不要把模型目录、程序目录、盘根或用户主目录当作题目工作区。

`CTFCode.exe` 使用受支持Windows 10/11内置的.NET Framework 4.x，不需要另装完整.NET SDK。当前未作代码签名，下载后可能出现Windows来源提示；请核验SHA256与来源，不要关闭系统防护或绕过安全警告。

自己的模型位置保存在包内 `local.json`，由入口生成，不需要编辑 JSON。换一个解压目录后，解释器、插件 URI 和启动参数会按新位置重新生成。不要把本机 `local.json`、会话或缓存再次打包上传。

## 硬件与资源

本版面向与参考机器相近的 Windows x64 + NVIDIA 消费显卡环境：参考为 8GB RTX 5060 Laptop、32GB RAM、20 核 CPU。需要兼容的 NVIDIA 驱动（0.1.59 manifest 最低 `580.65`）及充足 SSD 空间。

保留 16GiB 可用 RAM 加载门禁、1792MiB 显存预留、14GiB 工作集与 100ms 守护等保护，不会自动关掉你的应用。默认 32K；64K 是显式候选，不承诺任意后台负载下稳定或恒定 `10+ token/s`。

## 开发者如何复现构建？

定制源码位于 `portable/`，原生补丁与构建器见[定制CLI构建](定制CLI构建.md)。白名单构建器 `script/portable.py` 必须接收与 `v2/cli.json` 哈希相符的定制CLI，核验Control压缩包、Python wheel及引擎manifest全部字节；不再从旧版原版CLI压缩包取程序，不递归压缩旧工具箱。

先执行 `python script/launcher.py --output <新构建目录>` 生成小型入口和构建哈希，再向便携构建器显式提供 `--launcher <CTFCode.exe路径>`、`--cache`、`--cli`、`--engine32`、`--engine64`、`--output`；命令帮助用 `python script/portable.py build --help` 查看。组件仅进入Release，不提交Git。源码和二进制依赖仍受各自许可证约束，见包内 `licenses/`；模型/引擎指南及固定下载配置同时保存在包内 `文档/` 和 `config/`。
